# BIOFIN 서버 사용 매뉴얼

서버에서 재정 자료를 수집하고, BIOFIN 카테고리를 예측하고, 모델을 학습하는 방법을 설명합니다.
모든 작업은 **메뉴 프로그램 하나**(`biofin_menu.py`)에서 번호를 골라 실행합니다.
실제 작업은 서버의 Docker 컨테이너 안에서 돌아가므로 따로 설치할 프로그램은 없습니다.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 서버 접속 계정 | `coreit` |
| 작업 폴더 | `/home/coreit/biofin/biofin_cls3` |
| 메뉴 실행 | `python3 biofin_menu.py` |
| 실행 환경 | Docker 컨테이너 `biofin` |
| 수집 자료 위치 | `document/` |
| 예측·학습 결과 위치 | `transformer/v1/outputs/`, `llm/v1/outputs/` |

작업 폴더 구성은 다음과 같습니다.

```text
biofin_cls3/
├─ biofin_menu.py        메뉴 프로그램
├─ .env                  Open API 인증키 (외부에 공유 금지)
├─ crawlers/             수집 프로그램
├─ document/             수집한 목록(CSV)과 사업설명자료
├─ transformer/          Transformer 모델, 학습·예측 결과
└─ llm/                  LLM 분류 프로그램, 결과
```

## 2. 접속과 시작

1. 내 PC에서 PowerShell을 열고 서버에 접속합니다.

   ```powershell
   ssh coreit@<서버주소>
   ```

2. 작업 폴더로 이동해 메뉴를 실행합니다.

   ```bash
   cd ~/biofin/biofin_cls3
   python3 biofin_menu.py
   ```

3. 첫 화면에서 할 일을 번호로 고릅니다.

   ```text
   작업 선택
     1. 모델 학습
     2. 모델 예측
     3. 자료 수집 (크롤러)
   ```

## 3. 메뉴 공통 조작

- 질문 끝의 `[값]`은 기본값입니다. **Enter만 누르면 기본값**을 씁니다.
- 마지막에 실행할 명령어를 보여주고 `실행할까요? (y/N)`를 묻습니다. **`y`를 입력해야 실행**됩니다. 그 전까지는 아무것도 바뀌지 않습니다.
- 언제든 `Ctrl+C`를 누르면 취소됩니다.

파일이나 폴더를 고르는 화면에서는 다음 키를 씁니다.

| 입력 | 동작 |
|---|---|
| 번호 | 그 폴더로 들어가거나 그 파일을 선택 |
| `0` | 상위 폴더로 이동 |
| `s` | 지금 보고 있는 폴더를 선택 |
| `n` | 지금 위치에 새 결과 폴더 만들기 (결과 폴더 선택 화면에서만) |
| `q` | 취소 |

명령어만 확인하고 실행하지 않으려면 `python3 biofin_menu.py --dry-run`으로 시작합니다.

## 4. 자료 수집

첫 화면에서 `3`을 고릅니다. 수집 대상은 세 가지입니다.

| 번호 | 수집 대상 | 받는 것 |
|---|---|---|
| 1 | 지방재정365 | 지방자치단체 세부사업 목록, 사업별 상세 화면 PDF |
| 2 | 열린재정 | 중앙부처 세부사업 목록, 사업설명자료(HWP·PDF) |
| 3 | 열린재정 Open API 예산 목록 | 정부안금액·국회확정금액이 들어간 예산 목록 CSV |

### 4.1 지방재정365

차례로 다음을 묻습니다.

1. **회계연도**: 예) `2024`
2. **지역 선택**: 전국 17개 시도, 또는 직접 입력(예: `강원 세종`)
3. **기준일**: 기본값은 그 해 12월 31일입니다. 연간 확정 자료를 받으려면 그대로 둡니다.
4. **수집 범위**: `목록만` 또는 `목록 + 상세 PDF`
5. **지역별 최대 사업 수**: 기본값 `5`는 시험용입니다. **전체를 받으려면 `0`**을 입력합니다.
6. **저장 폴더 이름**: 기본값은 지역이 하나면 `강원_2024`, 여러 개면 `지방재정_2024`입니다.

저장 위치:

```text
document/<폴더 이름>/<폴더 이름>.csv       사업 목록과 수집 상태
document/<폴더 이름>/사업설명자료/         사업별 PDF
```

걸리는 시간은 목록만 받을 때 시도 하나에 수 초~수십 초이고, PDF는 사업 1건에 2~3초입니다.
강원도처럼 사업이 3만 건이 넘는 지역은 PDF까지 받으면 하루 이상 걸립니다.

### 4.2 열린재정

1. **회계연도**
2. **수집 범위**: `목록만` 또는 `목록 + 사업설명자료`
3. **최대 사업 수**: 시험은 `5`, 전체는 `0`
4. **상위 폴더 이름**: 기본값 `-`를 그대로 두면 `document/<연도>/`에 저장합니다.

저장 위치:

```text
document/<연도>/open_fiscal_<연도>.csv          사업 목록, 예산액, 다운로드 상태
document/<연도>/open_fiscal_<연도>_failed.csv   받지 못한 사업과 사유
document/<연도>/사업설명자료/                    HWP·PDF 문서
```

한 해 사업은 9천 건 안팎이고 1건에 약 2초가 걸려, 전체 수집에 4~6시간이 걸립니다.

알아둘 점:

- **국회에서 확정된 예산 기준**의 사업설명자료를 받습니다. 정부안 단계의 문서는 받지 않습니다.
- 사업설명자료가 원래 없는 사업은 CSV의 `다운로드상태`에 `no_document`로 기록됩니다. 오류가 아닙니다.

### 4.3 열린재정 Open API 예산 목록

회계연도, 최대 사업 수(전체는 `0`), 저장 폴더 이름을 묻습니다. 한 해 전체가 20초 정도면 끝납니다.

```text
document/<폴더 이름>/<폴더 이름>.csv
```

이 목록에는 사업설명자료와 사업 코드가 없습니다. 예산액의 공식 출처가 필요하거나 4.2의 목록에 빠진 사업이 없는지 점검할 때 씁니다.

### 4.4 수집하다가 나오는 질문

**"컨테이너에 수집에 필요한 프로그램이 없습니다. 지금 설치할까요?"**

문서까지 받는 수집을 처음 실행하면 나옵니다. `y`를 누르면 몇 분 동안 자동으로 설치한 뒤 수집을 이어갑니다.
한 번 설치하면 다시 묻지 않습니다. 다만 컨테이너를 새로 만들면 다시 묻습니다.

**"이미 있는 폴더입니다. 이 폴더를 사용할까요?"**

같은 이름의 폴더가 이미 있을 때 나옵니다. 이어서 받으려면 `y`, 다른 이름을 쓰려면 `n`을 누릅니다.

**"인증키 없이는 5건까지만 받을 수 있습니다"**

`.env` 파일에 인증키가 없다는 뜻입니다. 9.2절을 참고해 인증키를 넣습니다.

### 4.5 중간에 멈췄을 때 이어받기

메뉴에서 **같은 연도(같은 지역), 같은 폴더 이름**으로 다시 실행합니다.
이미 받은 사업은 건너뛰고 못 받은 사업부터 이어서 받습니다.

- 폴더 이름을 다르게 주면 처음부터 다시 받습니다.
- 폴더 안의 CSV 파일이 진행 기록입니다. **지우거나 엑셀에서 열어 저장하지 마세요.** 엑셀로 저장하면 큰 금액이 `1.9E+11`처럼 바뀌고 일부 글자가 깨집니다. 내용을 보려면 복사본을 여세요.

## 5. 모델 예측

첫 화면에서 `2`를 고릅니다.

1. **모델 선택**: `Transformer`, `LLM (Ollama)`, `LLM (vLLM API)` 중 하나
   - `LLM (vLLM API)`를 고르면 **분류 프롬프트 버전**을 한 번 더 묻습니다. `1. V1 (기존 프롬프트)`(Enter 기본값) 또는 `2. V2 (분류지침 개정 2026.10.22 반영)` 중 고릅니다.
2. **입력 CSV**: 예측할 사업 목록. `document` 폴더에서 시작하니 번호로 찾아 들어가 선택합니다.
3. **사업설명자료 폴더**: 역시 `document`에서 시작합니다. 문서가 들어 있는 폴더로 이동한 뒤 `s`를 누릅니다.
4. **결과 저장 폴더**: `n`을 누르고 Enter를 치면 날짜·시간 이름으로 새 폴더가 정해집니다.
5. 모델별 추가 질문은 대부분 Enter로 기본값을 쓰면 됩니다.

| 모델 | 추가로 묻는 것 | 결과 위치 |
|---|---|---|
| Transformer | 컨테이너 이름, 학습된 모델 폴더, 파일명 컬럼 | `transformer/v1/outputs/<날짜_시간>/` |
| LLM (Ollama) | Ollama 주소, 모델 이름, 문서 길이, 컨텍스트 크기 | `llm/v1/outputs/<날짜_시간>/` |
| LLM (vLLM API) | 프롬프트 버전, API 주소, 모델 ID, 문서 길이, 응답 길이, 동시 요청 수 | `llm/v1/outputs/<날짜_시간>/` (V2는 `<날짜_시간>_v2/`) |

입력 CSV에 필요한 것:

- `회계연도`, `소관명`, `세부사업명` 컬럼
- 문서 파일 이름이 적힌 컬럼. 기본 이름은 `사업설명자료_파일명`이고, 다르면 "파일명 컬럼" 질문에서 실제 이름을 입력합니다.

4장에서 수집한 목록 CSV는 열린재정과 지방재정365 모두 이 형식으로 저장되므로 바로 예측에 쓸 수 있습니다.
지방재정365에는 프로그램명과 단위사업명이 없어서 LLM 분류는 그 두 항목 없이 판단합니다.

LLM 예측은 Ollama 또는 vLLM 서버가 미리 켜져 있어야 합니다. 메뉴가 서버를 켜 주지는 않습니다.

## 6. 모델 학습

첫 화면에서 `1`을 고릅니다. Transformer만 실제 학습을 합니다.
LLM은 "학습"을 골라도 같은 분류를 실행할 뿐 모델을 새로 학습하지 않습니다.

1. **모델 선택**: `Transformer`
2. **학습 데이터 선택**: `원본만 사용` 또는 `원본 + 증강 통합 CSV 사용`
3. **입력 CSV**: 정답이 들어 있는 학습용 CSV
4. **사업설명자료 폴더**: 학습용 문서 폴더(`s`로 선택)
5. **결과 저장 폴더**: `n` → Enter
6. **다수 클래스 언더샘플링**, **클래스 가중치**: 잘 모르면 기본값(사용)을 둡니다.

학습된 모델은 고른 결과 폴더에 저장됩니다. 예측할 때 "학습된 모델 폴더"로 이 폴더를 선택하면 새 모델로 예측합니다.

증강 통합 CSV를 고르면 `row_type`, `training_eligible` 컬럼이 있는 파일만 받아들입니다.

## 7. 결과를 내 PC로 가져오기

내 PC의 PowerShell에서 실행합니다(서버에 접속한 창이 아닙니다).

```powershell
scp -r coreit@<서버주소>:/home/coreit/biofin/biofin_cls3/transformer/v1/outputs/<결과폴더> .
```

`<결과폴더>`만 실제 이름으로 바꿉니다. 마지막의 `.`은 "지금 폴더에 저장"이라는 뜻입니다.
수집한 목록 CSV 하나만 가져오려면:

```powershell
scp coreit@<서버주소>:/home/coreit/biofin/biofin_cls3/document/2024/open_fiscal_2024.csv .
```

## 8. 자주 쓰는 관리 작업

### 8.1 오래 걸리는 작업을 접속이 끊겨도 계속 돌리기

전체 수집이나 학습은 몇 시간씩 걸립니다. 서버 접속이 끊기면 작업도 멈추므로, `tmux` 안에서 메뉴를 실행합니다.

```bash
tmux new -s biofin
cd ~/biofin/biofin_cls3
python3 biofin_menu.py
```

- 작업을 돌려 둔 채 빠져나오기: `Ctrl+B`를 누른 뒤 `D`
- 다시 들어가서 진행 상황 보기: `tmux attach -t biofin`
- `tmux: command not found`가 나오면 서버에 설치되어 있지 않은 것이니 관리자에게 요청합니다.

### 8.2 폴더 지우기

수집·예측·학습 결과 폴더는 컨테이너가 만든 것이라 일반 삭제 명령(`rm`)으로는 지워지지 않습니다.
컨테이너를 통해 지웁니다. 컨테이너 안에서는 작업 폴더가 `/work/biofin_cls3`입니다.

```bash
docker exec biofin ls /work/biofin_cls3/document
docker exec biofin rm -r /work/biofin_cls3/document/<지울 폴더>
```

첫 줄로 이름을 확인한 뒤 둘째 줄로 지웁니다. **지운 폴더는 복구할 수 없습니다.**

### 8.3 컨테이너가 꺼져 있을 때

```bash
docker ps --format '{{.Names}}  {{.Status}}' | grep biofin
docker start biofin
```

첫 줄에 `biofin  Up …`이 보이면 켜져 있는 것입니다. 보이지 않으면 둘째 줄로 켭니다.

## 9. 문제가 생겼을 때

### 9.1 증상별 해결

| 증상 | 원인과 해결 |
|---|---|
| `Error response from daemon: container … is not running` | 컨테이너가 꺼져 있습니다. 8.3절대로 켭니다. |
| `실행 스크립트가 없습니다` | 작업 폴더가 아닌 곳에서 메뉴를 실행했습니다. `cd ~/biofin/biofin_cls3` 후 다시 실행합니다. |
| `crawlers 폴더가 없습니다` | 작업 폴더에 `crawlers/`가 없습니다. 관리자에게 요청합니다. |
| `ERROR-290 인증키가 유효하지 않습니다` | `.env`의 인증키가 틀렸거나 만료됐습니다. 한 번 더 실행해도 같으면 9.2절대로 인증키를 다시 넣습니다. |
| `ERROR-337 일별 트래픽 제한` | 하루 호출 한도를 넘었습니다. 다음 날 다시 실행하면 이어서 받습니다. |
| 수집이 "완료, 실패 0건"인데 문서가 하나도 없음 | 사이트가 개편된 것입니다. 9.3절을 봅니다. |
| 수집 중 일부만 `failed` | 일시적인 접속 문제일 수 있습니다. 같은 폴더로 다시 실행하면 실패한 것만 다시 받습니다. |
| `rm: cannot remove …: Permission denied` | 컨테이너가 만든 폴더입니다. 8.2절의 방법으로 지웁니다. |
| 설치 질문에서 `y`를 눌렀는데 설치 실패 | 컨테이너가 인터넷에 접속하지 못하는 경우입니다. 화면의 오류 내용을 관리자에게 전달합니다. |

### 9.2 인증키 넣기

인증키는 작업 폴더의 `.env` 파일에 있습니다.

```bash
nano ~/biofin/biofin_cls3/.env
```

`=` 뒤에 따옴표와 공백 없이 인증키를 붙여 넣고, `Ctrl+O` → Enter로 저장한 뒤 `Ctrl+X`로 닫습니다.

```text
OPENFISCAL_API_KEY=여기에_열린재정_인증키
LOFIN365_API_KEY=여기에_지방재정365_인증키
```

| 인증키 | 발급하는 곳 |
|---|---|
| 열린재정 | <https://www.openfiscaldata.go.kr/op/ko/ds/UOPKODSA03> |
| 지방재정365 | <https://www.lofin365.go.kr/portal/LF5100000.do> → "세부사업별 세출현황" 선택 → 인증키 신청 |

인증키는 발급받은 기관의 명의로 관리됩니다. 담당 기관이 바뀌면 새로 발급받아 교체합니다.

### 9.3 사이트가 개편되면

수집 방식은 두 가지가 섞여 있습니다.

| 수집 대상 | 방식 | 사이트 개편의 영향 |
|---|---|---|
| 지방재정365 목록 | 정식 Open API | 거의 없음 |
| 열린재정 Open API 예산 목록 | 정식 Open API | 거의 없음 |
| 지방재정365 상세 PDF | 화면을 열어 저장 | 화면이 바뀌면 멈출 수 있음 |
| 열린재정 목록·사업설명자료 | 화면이 쓰는 내부 주소 호출 | 화면이 바뀌면 멈출 수 있음 |

정식 Open API가 사업설명자료와 상세 화면 내용을 제공하지 않아서 아래 두 가지는 화면 수집을 유지하고 있습니다.
화면 수집은 사이트가 바뀌면 프로그램을 고쳐야 합니다.

실제 사례: 2026년 9월 열린재정이 "예산확정구분" 조건을 추가하면서, 수집이 오류 없이 끝나는데 문서가 하나도 받아지지 않는 일이 있었습니다.
**"실패 0건인데 문서가 없다"면 사이트 개편을 먼저 의심**하고 개발 담당자에게 알립니다.

## 10. 관리자 참고

### 10.1 프로그램 갱신

프로그램 원본은 GitHub 저장소 `biofin-research`에 있고, 서버에는 파일을 복사해서 씁니다.
수정한 파일은 내 PC의 PowerShell에서 서버로 보냅니다.

```powershell
cd C:\repos\biofin-research
scp biofin-cli\biofin_menu.py coreit@<서버주소>:/home/coreit/biofin/biofin_cls3/
tar -czf crawlers.tar.gz --exclude=outputs --exclude=biofin_continuity_outputs --exclude=label_comparison_20260910 crawlers
scp crawlers.tar.gz coreit@<서버주소>:/home/coreit/biofin/biofin_cls3/
```

서버에서 압축을 풉니다.

```bash
cd ~/biofin/biofin_cls3
tar -xzf crawlers.tar.gz && rm crawlers.tar.gz
```

### 10.2 실행 환경

- 컨테이너 `biofin`은 `biofin-cls3-env` 이미지로 만들어졌고, 서버의 `/home/coreit/biofin`이 컨테이너의 `/work`로 연결되어 있습니다.
- 이 이미지는 설정 파일(Dockerfile) 없이 만들어졌습니다. 설치된 패키지 목록은 `docker exec biofin pip freeze > environment_pip_freeze.txt`로 뽑아 둘 수 있습니다. **다른 서버로 옮기려면 이 목록으로 환경을 다시 구성해야 합니다.**
- 수집용 프로그램(Playwright, Chromium 등)은 메뉴가 컨테이너 안에 설치한 것이라, 컨테이너를 새로 만들면 사라집니다. 수집을 다시 실행하면 메뉴가 다시 설치를 묻습니다.
- LLM 분류는 `biofin` 컨테이너가 아니라 `python:3.11-slim` 컨테이너를 그때그때 새로 띄워 실행하고, 필요한 패키지는 `llm/.packages`에서 읽습니다.
- `_backup_biofin_cls/`에는 예전 `biofin_cls` 폴더의 Dockerfile과 `docker-compose.yml`을 보관해 두었습니다. `docker-compose.yml`은 데이터베이스 컨테이너 `biofin_db`의 설정입니다.
